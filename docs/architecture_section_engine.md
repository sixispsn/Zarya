# Движок «План - принципиальный разрез»

Этот слой строит архитектурную основу принципиальной схемы по подтвержденным
планам. Он отделен от движка К1/К2: сначала проверяется архитектура, затем к
готовым помещениям и шахтам привязывается канализация.

## Входные данные

Нормализованный JSON-реестр содержит:

- линию разреза с координатами начала и конца;
- этажи, отметки и чистые высоты;
- прямоугольные контуры помещений с номером, названием и ссылкой на источник;
- шахты и противопожарные преграды с координатами и ссылкой на АР/КР.

Для PDF предусмотрен второй, эквивалентный вход: подтвержденные интервалы вдоль
линии разреза. Каждый интервал хранит начало и конец, ID, номер, название и тип
помещения. Он не превращается в выдуманный прямоугольник плана.

Контрольный пример: `demo/architecture_section_registry.json`.

## Строгие проверки

Движок не строит лист, если:

- линия разреза не покрыта помещениями по всей длине;
- помещения перекрываются вдоль линии разреза;
- нет номера, названия либо ссылки на источник;
- преграда не пересекает линию разреза;
- повторяются идентификаторы этажей, помещений или преград.

Повторяющиеся этажи сокращаются только при полном совпадении структуры,
геометрии и назначения помещений. Номера помещений при этом сохраняются у
каждого этажа в модели.

## Выходные данные

`ArchitectureSectionModel` содержит упорядоченные ячейки помещений,
пересеченные линией разреза, отметки, шахты и преграды. Адаптер
`architecture_section_to_wastewater_layout()` переводит проверенную архитектуру
в координатную модель существующего движка К1/К2 без создания фиктивных комнат.

Следующий реестр `ConfirmedArchitectureWastewaterBinding` связывает с этой
архитектурой инженерные данные:

- положение каждого стояка на каждом подтвержденном этаже и его шахту;
- явное смещение стояка относительно этажа ниже;
- конкретный элемент проектного реестра, помещение и координату прибора;
- высоту подключения, DN, количество и целевой стояк;
- ссылку на лист/помещение АР для каждой строки.

Названия помещений не используются для автоматической расстановки. Функция
`build_bound_wastewater_layout()` совмещает координаты только с существующим
графом `project.sewage`. Неполная цепь приборов, неизвестный участок, стояк вне
шахты, прибор вне помещения, неподтвержденное смещение и унитаз менее DN100
блокируют сборку. А1-лист собирает
`generate_bound_architecture_wastewater_pdf()`.

Контрольный A1-лист можно собрать через
`generate_architecture_section_node_pdf()` из `app.pz.generator`.

## Граница текущего этапа

Страница `/wizard/architecture` открывает рабочее место подтверждения PDF. Она:

- отличает векторный лист от растрового;
- показывает наблюдаемые линии и текст исходного листа;
- принимает калибровку по двум точкам и известному размеру;
- принимает прямую линию разреза;
- показывает пересечения PDF-линий только как границы-кандидаты;
- строит интервалы только по выбранным проектировщиком границам;
- требует номер и название каждого помещения;
- сохраняет подтвержденные этажи с контрольной суммой исходного PDF.

После подтверждения архитектуры в том же рабочем месте открывается свёрнутый
инженерный шлюз. В нём отдельно добавляются положения стояков и приёмников
стоков. Реестр хранится рядом с PDF в файле с правами `0600`, проходит аудит и
восстанавливается после обновления страницы.

Исходный PDF и подтверждения временно хранятся в закрытой локальной сессии с
правами `0700/0600`. Подмена файла обнаруживается по SHA-256; сессию можно
удалить из рабочего места. После обновления страницы подтвержденная модель
восстанавливается.

Автоматически найденные элементы не становятся проектными решениями. Сейчас
поддержан прямой принципиальный разрез по векторному PDF и подтвержденные
помещения нескольких этажей. Шахты и противопожарные преграды пока задаются в
реестре, а их графическое подтверждение, DWG/IFC и произвольные ломаные разрезы
остаются следующими входными слоями.
