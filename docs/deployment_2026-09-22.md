## Предрелизные исправления

1. Файлы снимка могли иметь права 0600. Dockerfile нормализует только права
   чтения исходников внутри образа и проверяет импорт приложения после
   переключения на непривилегированного пользователя. Права локальных файлов
   пользователя и серверных секретов не меняются.
2. Навигационный тест теперь проверяет общий `site_header.html` и фактические
   HTTP-страницы, а не требует дублирования ссылки в каждом исходном шаблоне.
3. Отрицательный контрольный пример дополнен уже согласованной проверкой
   паспортных минимумов водомеров CALC-03. Основание — AGENTS.md, правила 16/22,
   `tests/test_meter_normative_corrections.py` и аудит от 20–21.09.
   Это **пятый ожидаемый блокер**, а не разрешение выпуска и не отключение проверки.
4. Тест существующего листа А1 исправлен на 841 × 594 мм; геометрия генератора
   и масштаб текста не менялись. Прежнее ожидание 420 × 594 противоречило
   названию теста и контракту А1.

## Переключение и откат

Обновляется только `app` в существующем Compose-проекте `zarya`.
Caddy, сертификаты, пароль и том `zarya_zarya_projects` остаются прежними.
Studio хранит данные в `/data/projects/_studio`, внутри постоянного тома.

Перед переключением: краткая приостановка записи, проверяемый tar.gz тома,
копии конфигурации с правами 0600 для `.env`, отдельная метка прежнего образа.
При неуспешном healthcheck сценарий автоматически возвращает прежний образ.

После успешной выкладки актуальная конфигурация доступна через
`/opt/zarya-releases/current`. Не выполнять старый `git pull && compose up`
из `/opt/Zarya`: этот Git checkout не содержит текущего снимка.

SHA-256 резервной копии тома перед обновлением:
`ae7a2b6f99e8723ed10bc77893bb3baa39aca773e187f4298c07077a152592ba`.

Команда ручного отката приложения (данные не удаляет и не восстанавливает):

```sh
docker compose --env-file /opt/Zarya/.env -p zarya \
  -f /opt/Zarya/compose.yaml \
  -f /opt/zarya-releases/20260922-2b3de38ecc3c/rollback.override.yaml \
  up -d --no-build --no-deps --wait --wait-timeout 90 app
```

Резервная копия данных находится в каталоге `backup` данного релиза.
Откат данных — отдельное решение: он может стереть новые проекты, созданные
после обновления; автоматически его выполнять нельзя.
