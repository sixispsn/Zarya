## Результат и границы

После создания предварительных PDF Studio использует свежий отчёт сборки.
Семь проверок наличия ПЗ, балансов, спецификации и схем закрываются по
реально существующим непустым файлам. Сам факт сборки не подтверждает
расчёты, решения или полноту содержания и не снимает запрет выпуска.

Повторный расчёт и попытка выпуска также используют эти сведения, но только
при совпадении принятых исходных и версии приложения. Файлы проверяются
повторно в приватном каталоге проекта; изменение исходных или версии
отзывает старые ссылки. Неподтверждённые старые метаданные не принимаются.

Пустая причина непроверенности К2 заменена конкретным перечнем недостающих
сведений об элементах сети. Уже рассчитанный расход кровли остаётся
рассчитанным. Проверки и инженерные формулы не менялись.

18 полей К2 и фановой группы остаются неопубликованными: их перенос —
следующий отдельный шаг. Проверочный сценарий явно фиксирует ровно этот
список, а не молча принимает отсутствующие поля как введённые данные.

## Состав выпуска

`scripts/stage_preview_readiness_release.py` переносит только относящиеся
к исправлению фрагменты четырёх файлов поверх предыдущего образа:

- `app/intake/studio_project.py` — обновление отчёта и версия представления;
- `app/web/studio.py` — жизненный цикл предпросмотра и повторного расчёта;
- `app/pz/ios2_orchestrator.py` — единая проверка наличия файлов комплекта;
- `app/pz/commission.py` — непустое пояснение К2.

Манифест содержит исходные и новые SHA-256. Полные деревья app/demo/legacy
сравнены: изменены ровно четыре файла, остальные 403 совпадают. Работающий
контейнер соответствует проверенному образу. Авторизация, срок сессий,
Caddy/TLS, схема хранилища и расчётное ядро не менялись. Git commit/push
не выполнялись: накопленные несвязанные изменения не включены в выпуск.

Обе копии legacy сохранили контрольные суммы:

- рабочая: `00a14a5b5ec9a195894db4da92e2439b6453f4e71e34e89a48c5b622e68068e4`;
- архивная: `ace54b14e2f30fadaec768ec06aa5a326553709b9a869263208ef8ee58df3788`.

## Проверки

145 профильных тестов прошли: Studio, предпросмотр, группировка замечаний,
нормативная матрица, оркестратор, PDF-комплекты, рабочий legacy и доступ
участников. Это не весь репозиторий. Новые регрессии воспроизвели ошибки
до исправления и проверяют сохранение чисел/блокировок, удалённый файл,
повторный расчёт, изменение версии и отзыв доступа.

Серверный сценарий выполнен сначала без внешней сети, портов и рабочего тома,
затем через настоящий HTTPS под двумя временными участниками:

- вход, загрузка PDF, расчёт, сборка и скачивание ИОС2/ИОС3;
- 404 для чужих файлов и запрет доступа в общий старый редактор/админку;
- CSRF, выход, отзыв ссылок после изменения данных;
- семь статусов сохраняются при повторном расчёте и попытке выпуска;
- выпуск по-прежнему блокируется инженерными замечаниями;
- временные ключи отозваны, прежние записи участников не изменены.

После сборки остаются 33 строки замечаний, включая два сводных статуса
DOC-04/DOC-05. Из них 22 блокирующие. Прежние 19 блокировок не сняты;
наружный план V-GOST-A07 действительно отсутствует и теперь блокирует
вместо статуса ожидания. Сводные строки повторяют отдельные основания,
а не создают новые инженерные задачи.

Все численные группы до и после предпросмотра совпали. Водомеры DN50/32/32,
потери 1,451/3,479/4,703 м, паспортные Qmin 0,45/0,12/0,12 м³/ч;
отсутствующий минимум потребления здания не подменяется паспортным.
В2 сохраняет 45/45 исследованных режимов, не становясь полным подтверждением
покрытия здания или паспорта станции. Зафиксированный пример Самары
сохранил 52 страницы в изолированном прогоне.

Проверочные файлы: `output/pdf/preview-readiness-smoke/` и
`output/pdf/live-preview-readiness/`. ИОС2 — 46 страниц / 20 закладок,
ИОС3 — 12 / 3. Все 58 страниц сравнены по растру с предыдущим выпуском;
закладки совпадают. PDF с сайта побайтно совпадают с изолированной выдачей
и предыдущим выпуском. Через Poppler дополнительно просмотрены лист ВУ,
разрез К1/К2 и лист спецификации. Это контроль отсутствия регрессии,
не финальная приёмка оформления или снятие известных замечаний чертежей.

Состав проверяется по локальным текстам ГОСТ Р 21.619-2023 (п. 5.1.21,
пп. 5.2.2.3–5.2.2.6) и ГОСТ Р 21.620-2023 (п. 5.1.3.3,
пп. 5.2.2–5.2.4). Состав и оформление документов этим исправлением
не изменены; отсутствующие ручные материалы не объявлены готовыми.

При подготовке исправлены две ошибки проверочного окружения: разрешение
HTTP только для localhost изолированного контейнера и затенение переменной
снимка участников в QA-скрипте. Успешными считаются полные повторные прогоны.
Защита HTTPS рабочего сайта не ослаблялась.

Откат меняет только приложение, не заменяет актуальные данные старым архивом:

```sh
previous=/opt/zarya-releases/20261005-section-documents
docker compose --env-file "$previous/.env" -p zarya \
  -f "$previous/compose.yaml" -f "$previous/base.override.yaml" \
  -f "$previous/release.override.yaml" \
  up -d --no-deps --no-build --wait --wait-timeout 90 app
ln -sfn "$previous" /opt/zarya-releases/current
```

После обновления старый предпросмотр нужно сформировать заново. Исходные
и сохранённые проекты не удаляются. По фиксированным весам плана прогресс
остаётся 55%: часть следующего подпункта завершена, но передача исходных
и подтверждение решений ещё впереди.
