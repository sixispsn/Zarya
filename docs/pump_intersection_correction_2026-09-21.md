# L04 — границы кривой и подтверждённое пересечение

21.09.2026. Исправление согласовано отдельным продолжением пользователя.
Оригинал `legacy/sp30_calculator.html` не менялся: SHA-256
`ace54b14e2f30fadaec768ec06aa5a326553709b9a869263208ef8ee58df3788`.

## Причина

Архивный `interpH` обнулял последнюю известную точку, например CR 10-4:
Q=11 м³/ч, Hкат=16 м, результат функции 0. `findWorkingPoint` выбирал
минимальную невязку из 201 отсчёта без проверки пересечения.

## Исправление и границы

- Один модуль `app/calc/pump_curve.py` для расчётного ядра и графических helpers.
- Интерполяция на закрытом опубликованном диапазоне, вне него — None.
- Для каждого линейного сегмента каталог/система разбиваются в точках
  включения нулевого ограничения L02 и экстремума невязки. На монотонных
  интервалах со сменой знака — бисекция; концы и касания проверяются отдельно.
- Возвращаются статусы unique / none / ambiguous / invalid. Несколько корней
  или совпадающий участок не превращаются в произвольно выбранную точку.
- Допуск невязки 1e-9 м — численный, не разрешённый инженерный недобор.
- Q/H пересечения не округляются при сохранении. Формат таблицы/графика
  остаётся прежним: Q до 0,01 м³/ч, H до 0,1 м.
- Если Q/H обеспечивается, но пересечение вне каталога, сообщение прямо
  разделяет эти факты. Нет экстраполяции и нет автоматической модели ЧРП.
- CALC-04 перепроверяет сохранённое пересечение для quadratic_estimate;
  неподтверждённый старый результат требует пересчёта. В PDF его рабочий
  маркер скрыт, подпись предупреждает об этом; сохранённые данные не затираются.
- В2 при известных только Q/H остаётся duty_only: без выдуманной сети.

Каталоги, формула сети L02, геометрия, правила рейтинга и проверки NPSH не
заменялись. L05 (выход водомера за каталог) этим разрешением не исправляется.
Это математическая корректировка, не новый нормативный метод гидравлики.

## Проверки

`tests/test_pump_curve_intersection.py`: независимые аналитические решения,
обе границы, отсутствие пересечения выше/ниже каталога, касание, два корня
в одном сегменте, совпадение, отрицательный H0, k=0, некорректные кривые,
три режима, API на последней точке, сохранённые устаревшие результаты.

`scripts/legacy_pumps_reference.mjs` включает поправки L02/L03/L04 только
явными флагами. Для L04 JS решает квадратное уравнение аналитически,
независимо от бисекции Python. Проверяется весь каталог при четырёх
сочетаниях H0/k и 120 воспроизводимых немонотонных кривых. Оригинальный JS
без флагов сохраняет исходные ошибочные числа и контрольную сумму.

PDF: `venv/bin/python scripts/preview_l02_pumps.py --case l04`.
Контрольный расчёт на условных исходных данных, не комплект реального здания.
Проверка оформления по ГОСТ Р 21.619-2023, п. 5.1.8: составляющие напора,
расчётная пара, предварительный вариант, Q/H, мощность, резерв, NPSH и
график приведены в самостоятельных листах в рамке. Это не утверждение
о готовности всего проекта/здания: регулирование, давления и актуальность
архивных характеристик остаются предметом отдельной проверки.
Баланс и остальные разделы ПЗ этим исправлением не менялись.

Расширенный прогон: **2012 passed, 2 failed**. Оба оставшихся сбоя — ранее
известные тесты `test_release_blocker_regression`: контрольный пример теперь
выдаёт CALC-03 из-за отсутствия паспорта DN40 и минимальных расходов водомеров,

ожидания не подменялись в рамках L04. Ruff изменённых расчётных файлов проходит.
