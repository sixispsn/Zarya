# Публикация раздельных комплектов ИОС2 и ИОС3

5 октября 2026 года на zaryaproekt.ru опубликованы ссылки «ИОС2 одним PDF»,
«ИОС3 одним PDF» и три группы замечаний: вода, канализация, общие сведения.
Это доступ к предварительным документам, а не снятие проверок выпуска.
Второй этап согласованного плана завершён: общий прогресс 45 из 100%.

## Состав и воспроизводимость

Образ `zarya-release:20261005-section-documents`, ID `c86e748db4e2`,
build ID `section-documents-20261005`. Каталог сервера:
`/opt/zarya-releases/20261005-section-documents`.
Предыдущая версия `20261005-meter-products` сохранена для отката.

`scripts/stage_section_documents_release.py` формирует девять runtime-файлов:
два новых модуля сборки ИОС2 и группировки замечаний, PDF merge, оркестратор,
каталоги документов Wizard/Studio, представление результата, JavaScript и
ключ кеша шаблона. В `studio_project.py` и `studio.js` перенесены только
относящиеся к задаче фрагменты. Неопубликованные вопросы канализационной
анкеты и фановой вентиляции исключены.

Полные деревья app/demo/legacy до и после сборки сравнены по SHA-256:
изменены ровно девять файлов манифеста, остальные 398 не изменены.
Работающий контейнер побайтно соответствует проверенному образу.
Авторизация, сроки сессий, Caddy/TLS, хранилище и расчётные алгоритмы не менялись.
Git commit/push не выполнялись. Манифест, исходные и новые хеши, Dockerfile,
скрипты проверки и активации сохранены в каталоге выпуска; несвязанные правки
рабочей папки в него не вошли.

Рабочий legacy сохранил SHA-256
`00a14a5b5ec9a195894db4da92e2439b6453f4e71e34e89a48c5b622e68068e4`.
Локальный исторический архив также не изменён.

## Проверки

Перед публикацией повторно прошли 83 теста: Wizard, предварительная выдача,
группировка, сборка и объединение PDF, рабочий legacy, контроль блокировок.
Это профильный прогон, не все тесты репозитория.

Новый образ проверен без внешней сети, опубликованных портов и рабочего тома.
После переключения тот же сценарий выполнен через настоящий HTTPS:

- Два временных участника; закрыты старый общий редактор и админка.
- Успешная загрузка PDF, чтение владельцем и 404 для другого участника.
- Расчёт обычного проекта через API Studio и формирование обоих комплектов.
- Водомеры DN50/32/32, потери 1,451/3,479/4,703 м; В2 — 45/45 режимов.
- Все группы расходов, напоров, насосов, водомеров, гидравлики и дождевого
  стока совпали с предыдущей опубликованной контрольной моделью.
- Все 38 действующих замечаний сохранены в трёх группах. Выпуск заблокирован,
  предварительные PDF доступны; сводное сообщение не считается лишней задачей.
- CSRF, приватность PDF, отзыв ссылок при изменении исходных и выход проверены.
- Временные ключи отозваны; прежние записи участников остались неизменными.
- Зафиксированный пример Самары сохранил 52 страницы в изолированном прогоне.

Проверочные файлы с сайта сохранены в `output/pdf/live-section-documents/`:

закладки совпали и ведут на действительные страницы. Все 46 страниц воды

Откат возвращает только приложение, не заменяет рабочие данные старой копией:

```sh
previous=/opt/zarya-releases/20261005-meter-products
docker compose --env-file "$previous/.env" -p zarya \
  -f "$previous/compose.yaml" -f "$previous/base.override.yaml" \
  -f "$previous/release.override.yaml" \
  up -d --no-deps --no-build --wait --wait-timeout 90 app
ln -sfn "$previous" /opt/zarya-releases/current
```

После обновления старый предварительный PDF может требовать повторного
расчёта и формирования: версия представления изменилась. Сами исходные
пользователя и ранее сохранённые проекты не удаляются.
