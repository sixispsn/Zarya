## Проверки расчётов и документов

Перед публикацией прошли 82 профильных теста, включая рабочий legacy.
Первый запуск шести parity-проверок не нашёл Node в PATH; повторный запуск
с явным NODE_BINARY прошёл. Это не расхождение вычислений.

Серверный образ проверен в контейнере без внешней сети, опубликованных портов
и подключения рабочего тома. Затем тот же сценарий выполнен через настоящий
HTTPS после переключения сайта. Использованы отдельные временные участники
и синтетические исходные контрольного примера, не объекты владельца.

- Водомеры: DN50/32/32; потери 1,451/3,479/4,703 м без изменений.
- Паспортные Qmin 0,45/0,12/0,12 м³/ч не подменяют отсутствующий минимум здания.
- Верхняя паспортная граница Δp ≤ 0,1 МПа при Qmax не превращена в S или h(Q).
- Все значения водомеров, напоров, насосов, расходов и пожарной станции

  выдачу. CSRF, закрытость старого редактора и админки проверены.
- Временные ключи отозваны, прежние записи участников не изменились.
- Фиксированный пример Самары сохраняет 52 страницы.

## Сохранность данных и откат

До переключения сделана согласованная резервная копия постоянного тома,
`backup/projects.tar.gz`, права 0600, SHA-256
`45425586848e25d7e2eacae6221e61b4aa33686cc073d503745280874bd75985`.
Она восстановлена отдельно в `restored-pre-meters` и проверена побайтно:
304 файла, 19 проектов, 8 черновиков, 219 PDF; 30 JSON разобраны,
SQLite integrity_check успешен. После переключения 301 прежний файл вне
служебных `_pilot` и `_normatives` совпал с резервной копией.

Откатывать только приложение, не заменять текущие данные старой копией:

```sh
previous=/opt/zarya-releases/20261005-studio-ios2
docker compose --env-file "$previous/.env" -p zarya \
  -f "$previous/compose.yaml" -f "$previous/base.override.yaml" \
  -f "$previous/release.override.yaml" \
  up -d --no-deps --no-build --wait --wait-timeout 90 app
ln -sfn "$previous" /opt/zarya-releases/current
```
