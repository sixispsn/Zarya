## Откат приложения

Не восстанавливать рабочие данные поверх новых объектов пользователей.
При необходимости вернуть только предыдущий образ:

```sh
previous=/opt/zarya-releases/20261002-section-design-ui
docker compose --env-file "$previous/.env" -p zarya \
  -f "$previous/compose.yaml" -f "$previous/base.override.yaml" \
  -f "$previous/release.override.yaml" \
  up -d --no-deps --no-build --wait --wait-timeout 90 app
ln -sfn "$previous" /opt/zarya-releases/current
```

Персональный вход сохраняется в предыдущем образе. Созданный новым примером
черновик может не открыться в старом коде; его не удалять и не подменять.
После отката потребуется вернуть выбранный проект участника, если он находился
в примере Самары. Обычные проекты и ключи не требуют миграции.

Git commit/push в этом заходе не выполнялись. Следующая инженерная задача —
отдельная проверка нового решения В2 в ремонтных режимах, без выдачи прежнего
fixed-Q отчёта за доказательство L06.
