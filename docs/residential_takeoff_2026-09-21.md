# Полная сеть К1/К2 и проверяемые количества

## Сделано

- `app/pz/network_takeoff.py`: граф физических экземпляров, участки с выбранным
  сортаментом, числовой длиной или явно незаданной длиной, происхождение и статус.
  Поддержан подсчёт длины 3D-ломаной в метрах с сохранением исходных точек.
- Каждый источник доходит до своего выпуска; запрещены циклы, смешение К1/К2,
  заглушка на проходном узле, отрицательные/нечисловые длины, двойной учёт ID.
- Группировка по системе, серии, наружному диаметру, стенке и статусу. DN не
  подставляется вместо внутреннего диаметра. Для компонентов учитывается серия.
- `small_residential_takeoff.py`: связка с существующей моделью восьми квартир,
  исходными этажными и подвальными монтажными узлами. Состав фасонины не
  заменяет их новой библиотекой. Количество штук целое, резерв не добавляется.
- В учебный экспорт Studio добавлена отдельная предварительная ведомость PDF
  `Объёмы_сети_К1_К2.pdf`; сервер сохраняет рядом JSON с ID и источниками.
  Хеш модели включает количествообразующую сеть. Трёхэтажный пример не получает
  чужую ведомость восьмиквартирного дома.
- Контрольный PDF объединяет существующую принципиальную схему и три страницы
  ведомости. Сама схема не перерисована. Проверены все четыре страницы.

## Исходные и границы точности

Учебный экспорт пока не использует обмер PDF. Отдельное рабочее место обмера и
программный адаптер к полной сети добавлены следующим шагом:
[состояние измерителя](plan_route_measurement_2026-09-21.md).
Учебное предложение задаёт 4 м общей квартирной
ветви, станции приборов 0,3 / 1,8 / 2,8 / 3,4 м и подводки
0,45 / 0,25 / 0,45 / 0,20 м. Врезка принята на +0,20 м от пола.
Это **не новые нормативные значения** и не глобальные значения по умолчанию.
Адаптер принимает их явно; на другой набор приборов молча не переносит.

Подвальные профили сохранены: К1 9 м, i=0,020; К2 6 м, i=0,015. Уклон
учитывается при переводе горизонтальной проекции в осевую протяжённость.
Стояки считаются по отметкам этажей, кровли и осей коллекторов один раз.
Для выпусков в этом примере явно предложено по 1,20 м до наружной грани стены.
Без этой длины участок остаётся в графе с `length_m=null`, а ведомость показывает
неполноту; отсутствующая длина не превращается в нулевое количество.

Полученная длина - **огибающая по теоретическим пересечениям осей**, включая
места фасонины. Это не чистая длина трубных отрезков: нет монтажных размеров
отводов, раструбов, раскроя и серийных длин. На текущем этапе `purchase_ready`
всегда false. Количество фитингов - состав предлагаемых узлов, не утверждённые
артикулы. Крепёж, муфты SML, изоляция, огнезаделка и манжеты не выдумываются:
перечислены как незавершённые части ведомости. Водоснабжение не включено.

## Ручной контроль для восьми квартир

- 32 санитарных прибора: по 8 моек, ванн, умывальников и унитазов; 4 воронки К2.
- 102 участка; 198 экземпляров компонентов (не все - отдельная закупочная позиция).
- К1 PP HT 50x1,8: `8 × (hypot(3,4; 3,4×0,03) + 0,45 + 0,25 + 0,45)`
  = 36,412 м осевой протяжённости.
- К1 PP HT 110x2,7: квартирные окончания + четыре стояка/вытяжные части +
  общий коллектор + опуск + выпуск = 48,344 м.
- К2 SML 110x3,5: четыре стояка + общий коллектор + опуск + выпуск = 39,107 м.
- Заглушки: 8 этажных DN50, одна начальная К1 DN100 и одна начальная К2 DN100.
  Проходные подвальные тройники не заглушаются.

Суммы - контроль реализации на **предложенных** трассах, не обещание такого
расхода материалов в реальном здании.

## Проверки и воспроизводимость

Прогон этого этапа: **256 passed, 17,51 с** (новый подсчёт, Studio, учебные
схемы/профили, спецификация, отметки воды, parity дождя и исправленный legacy).
Ruff новых модулей и `git diff --check` прошли. Полный набор проекта повторно
не запускался; четыре ранее известные проблемы общего прогона не закрывались.
Рабочий legacy и SHA-256 архивной версии проверены отдельной командой `--check`.

`tests/test_network_takeoff.py`: ручные суммы, скрытые на разрезе квартиры,
независимость от координат УГО, изменение одного исходного, незаданные длины,
дубликаты, К1/К2, заглушки, состав исходной фасонины, сгруппированные приборы,
3D-длина, разные серии и изменение хеша Studio. Синтетический тест 500 источников
проверяет только суммирование без умножения общего коллектора; это не проверка
проектирования 500-квартирного дома.

Генерация контрольного файла:

```sh
NODE_BINARY=/path/to/node PYTHONPATH=. venv/bin/python scripts/build_residential_takeoff_review.py
```

Перед PDF выполняется существующая исполняемая проверка расходов воды/дождя
с legacy. Никакие формулы расчётного ядра и архивный legacy не изменены.
Для состава контрольной схемы просмотрены пп. 5.2.2.1-5.2.2.4 предоставленного
ГОСТ Р 21.620-2023. Новая ведомость не объявлена нормативной СО или полным ИОС3.

## Следующий шаг

Обмер по подтверждённому масштабу и сохранение 3D-ломаных уже реализованы в
отдельном рабочем месте. Следом — выбор участка полной модели в интерфейсе,
явный перенос проверенных измерений в ведомость и проверка изменения узлов.
Затем подключить выбранные монтажные размеры фасонины и действительные
проходки, опоры, изоляцию. Параллельно нужен аналогичный адаптер полной сети воды;
расчётный диктующий путь В1 сам по себе не является ведомостью всего здания.
