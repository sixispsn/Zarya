По запросу Антона: последовательные окна «Здание» → «Подключение и ТУ» → «Потребители». Белая тема, равные колонки полей, лёгкая инфографика из трёх шагов и контурных пиктограмм. На телефоне одна колонка. Условный рисунок кровли из Studio убран; выбор вида и пояснение сохранены.

## Реализация и границы

- `studio_configurator.js` задаёт только группировку; каждый параметр анкеты представлен ровно в одном блоке. Формулы остаются на сервере в прежнем ядре.
- Подвал открывает отметку пола; дополнительные геометрия/водосток, геология/фундамент, условия ТУ и ручные расчётные параметры раскрываются отдельно.
- Новые контекстные поля: назначение, площадь/объём, чердак, фундамент, наличие геологии, грунты/воды, мерзлота/сейсмика, технологические потребители и режим работы. Площадь передаётся в существующее поле проекта. Остальной новый контекст сохраняется в анкете, но не выдаётся за реализованную детализацию конструктивных узлов или специальную расчётную методику.
- Нет данных о мерзлоте/сейсмике — не означает «нет». Известные особые условия и смешанное/индивидуальное назначение не должны молча превращаться в стандартный многоквартирный проект: полный комплект/передача блокируются с объяснением. Расходы выбранной жилой группы доступны отдельно.
- Анкета потребителей сохраняет прежнюю жилую группу, нормы, источник ГВС и предварительную оценку квартирного учёта. Кафе/прачечная/магазин не включаются в число жителей; для них ещё нужен отдельный сценарий групп.
- Предложенные типовые значения принимаются кнопкой «Далее»/«Рассчитать» только в показанном блоке. Другие источники PDF не подтверждаются скрыто. «Назад» сохраняет только изменённые поля. Escape сохраняет несохранённый ввод в текущем интерфейсе; уход со страницы предупреждает/сохраняет по прежней логике.
- Прогресс блоков означает заполненность основных полей, не одобрение проекта экспертизой.

## Тестовые объекты — обязательная следующая задача

Обновление того же дня: после согласования реализован первый этап архива, см. [объекты пилота](pilot_objects_2026-09-28.md). Ниже сохранён исходный план; загрузка финальных экспертных комплектов и статусы экспертизы остаются следующими этапами.

Антон попросил запоминать объекты пилота, затем запросить у тестеров варианты, прошедшие экспертизу, и использовать сравнение для развития ЗАРИ. Требование зафиксировано; отдельный архив неизменяемых версий в этом изменении **не реализован**. Текущие личные черновики продолжают сохраняться, но не заменяют такой архив.

Предлагаемый договор хранения (вопрос отправлен пользователю): отдельное подтверждение инженера «Сохранить объект пилота», доступ инженеру и владельцу ЗАРИ, без автоматического копирования исходных PDF. До согласования не расширять доступ владельца к личным документам и не включать скрытое архивирование.

Минимальная карточка после согласования: стабильный ID объекта, участник, разрешённое название/псевдоним, дата и версия сборки, ревизия исходных, снимок исходных/результатов с допущениями, статус «тест → передан → замечания → экспертиза пройдена», ссылка на отдельно разрешённый финальный комплект. Новая итерация не перезаписывает предыдущую. Выявленные изменения расчётных методик проходят отдельное обсуждение по AGENTS.md, не становятся автоматическим «обучением» ядра.
