## Принятое пользователем условие

19.09.2026 пользователь явно разрешил использовать нижний «План полов»
как план подвала **в учебном тесте генератора**.

- Контур и показанные перегородки принимаются как условная планировка подвала.
- Номера типов полов, покрытия и привязка к экспликации полов не становятся
  номерами помещений, оборудованием, приямками или санитарными приборами.
- Этот выбор не подтверждает существование такого подвала в исходном здании.
- В последующей выдаче основание обозначается: «Планировка подвала условно
  принята по фрагменту “План полов” по заданию пользователя».
- Нечитаемые размеры не восстанавливаются как точные проектные данные.
  Пропорции допустимы для графической компоновки, не для расчётных длин.

## Что не переносится из первого примера автоматически

Высота и отметка подвала, уровни этажей, число жителей, материал труб,
расчётные расходы, уклоны/длины коллекторов, отметки выпусков, параметры ТУ
и четыре воронки К2 из первого дома относятся к первому примеру.
Второй пример не изменяет `demo/residential_2floors_8apartments.yaml`.

Кровля на новом листе выглядит скатной; организация водоотвода и наличие
внутренней К2 пока не подтверждены. Источник не даёт основания переносить
плоскую кровлю +6,600 и четыре внутренних воронки первого дома.

## Исходная последовательность (заменена по замечанию пользователя)

Разметить основной план: квартиры, мокрые зоны, лестничные клетки,
предлагаемые стояки. Привязать их к условному подвалу, отдельно различая
считанные с рисунка элементы и предложенную трассировку. После согласования
получить принципиальный разрез. Первый дом сохранить как регрессионный пример.

## Выполнен шаг 1: привязка мокрых зон и условного подвала

После команды пользователя «газ» создан отдельный файл предложений
`demo/residential_second_layout.study.json`. Это не формат подтверждённого
Project: координаты нормализованы по растровой подложке, а метры/отметки,
жители и организация К2 остаются незаданными. Разметка выполнена вручную.

Предложено для проверки пользователем:

- четыре группы «кухня + санузел», по две в каждой секции;
- повторение на двух этажах: предварительно восемь квартир;
- четыре самостоятельных стояка К1;
- коллектор К1-М1: от К1-2 через проходное присоединение К1-1 к выпуску 1;
- коллектор К1-М2: от К1-3 через проходное присоединение К1-4 к выпуску 2;
- две соосные прочистки на свободных началах, не на проходных присоединениях.

Две ветви и два выпуска - предложение трассировки, не требование СП и не
решение, считанное с исходного листа. Ревизии по высоте, отступы от стен,
отметки/уклоны, диаметры и проходки ещё не назначены. Численные интервалы
обслуживания не проверены: нет калибровки длин. Расположение мокрых зон и
возможность общего стояка для кухни/санузла требуют согласования.

`app/architecture/residential_plan_study.py` строит направленные связи
16 групповых источников (не 16 отдельных приборов) с этажей до двух выходов.
Для свободного/проходного нижнего узла повторно используются существующие
канонические сборки. Их DN100 - только внутренний графический шаблон,
не назначенный диаметр второго дома; в PDF этот DN не публикуется.
Оси этажных и подвальных точек берутся из одних координат данных.
Выноски размещает существующий `LeaderLayoutEngine`.

## Внутренняя разметка и воспроизведение


Один лист А2: `output/pdf/Второй_дом_разметка_К1_и_подвала.pdf`.
Это лист согласования расположения, **не готовая принципиальная схема**.
В исходную картинку изменения не вносятся: на PDF наложены цветовые зоны
и предложенные связи. Фрагмент «План полов» остаётся растровой подложкой;
номера типов полов не превращены в элементы канализации.

Этот промежуточный лист пользователь исключил из целевой выдачи:
планы нужны на входе, результатом должна быть только принципиальная схема.

## Проверки и граница изменений

22 новых теста проходят: связность всех источников, отсутствие потери/дублей
стояков, направление по магистрали, раздельные выходы, соосный свободный
конец, запрет заглушения проходного узла, совпадение осей двух планов,
изменение координат через данные, отсутствие автоматического переноса
параметров первого дома. Целевые ruff и mypy проходят.

226 прежних целевых тестов также проходят, включая legacy parity и защиту
подписей уклонов первого дома. PDF просмотрен целиком и в увеличенном
фрагменте подвала. Расчётное ядро, прежние PDF, production Project и сайт
не менялись; commit/deploy не выполнялись.

## Исправление: выдаётся только принципиальный разрез

```sh
PYTHONPATH=. venv/bin/python scripts/build_second_residential_study.py
```

Результат: `output/pdf/Второй_дом_принципиальная_схема_К1.pdf`, один векторный
А2 без растровых подложек. Новый компоновщик `residential_plan_section.py`
показывает два этажа с кухнями/санузлами, лестничные клетки, четыре стояка,
индивидуальные фановые окончания, условный подвал и два выпуска. Условные
комнаты развёрнуты по порядку групп исходного плана; миллиметры листа не
являются метрами здания. Четыре типовых прибора на группу - интерпретация
для проверки компоновки, не подтверждённая спецификация исходного проекта.

Используются существующие векторные УГО, гидрозатворы, этажные фасонные
узлы, переход до унитаза и свободные/проходные подвальные присоединения.
От каждого из 32 приборов проверяется путь к выпуску своей секции. Ось
стояка едина на этажах и в подвале. Экспорт блокируется при потере стояка,
ветви, ревизии, обозначения незаданного уклона, прочистки начального узла
либо появлении заглушки на проходном узле.

Численные отметки нового дома не назначались, уклоны не копировались из
первого дома. На схеме они указаны как «н/д». DN50/100 из графического
шаблона обозначены звёздочкой и пояснением: это не гидравлический подбор.
Высота фанового окончания обозначена h* и требует данных о кровле.
1000 мм для ревизии - ранее принятое пользователем правило удобства
обслуживания, не автоматически приписанное требование СП. Места проходок,
противопожарные решения, длины обслуживания и новые численные привязки
подлежат уточнению. К2 из старого дома не перенесена.

При сборке просмотрены пп. 5.2.1–5.2.2.4 и приложение В предоставленного
ГОСТ Р 21.620-2023. Состав неполон из-за отсутствующих исходных данных,
поэтому `release_ready=False`; схема не регистрируется как выпуск ИОС3.

Для плотной компоновки выносок добавлен необязательный набор горизонтальных
смещений в существующий `LeaderLayoutEngine`; прежний набор по умолчанию
сохранён. 48 тестов новой/смежной функциональности и 226 регрессионных
прошли; ruff/mypy нового модуля проходят. Итоговый лист и увеличенные узлы
просмотрены. Legacy SHA-256 остался прежним, commit/deploy не выполнялись.
