# Закрытая альфа: замечания и удаление исходников — 27.09.2026

Развёрнуто на `https://zaryaproekt.ru/`. Персональная защита и прежний внешний Basic Auth сохранены. Ключ владельца не перевыпускался, реальные тестировщики не добавлялись.

## Что изменилось

- Кнопка «Сообщить о проблеме»: тема и текст до 4000 символов; после сохранения номер `ZR-…`. Передаются только эти поля, случайный идентификатор повторной отправки; имя участника и сборка добавляются сервером. PDF, параметры, URL/query, cookie, снимки экрана и тексты ошибок автоматически не прикладываются.
- Повтор запроса с тем же идентификатором не создаёт дубль; изменение текста уже отправленного запроса отклоняется. Лимит 20 новых сообщений в час на участника. Замечания сохраняются в таблице `feedback` существующей закрытой SQLite-базы в постоянном томе.
- Только владелец видит список `/access/feedback` (также «Справка → Замечания альфы»). Вывод экранирован, выдача по 50 сообщений. Это сбор замечаний, пока без статусов обработки и переписки.
- Крестик у исходного PDF открывает отдельное подтверждение. Несохранённый ручной ввод сначала сохраняется; удаление ограничено текущим личным черновиком и его ревизией.
- Удаляются оригинальный загруженный файл и извлечённые из него кандидаты. Подтверждённые только этим документом значения сбрасываются; свидетельства из оставшихся документов и ручные значения сохраняются. Расчёт, текущий предпросмотр, текущий комплект и ссылка на handoff инвалидируются.
- Удаление файла происходит после атомарного сохранения отзыва доступа. При сбое unlink остаётся приватная очередь очистки; следующее сохранение повторяет очистку. Ошибка не выдаётся за успешное удаление.

Граница удаления раскрыта в окне: ранее созданные PDF, исторические проекты/комплекты, скачанные копии и резервные копии не удаляются. Это не полное стирание всех производных данных. Политика сроков хранения, удаление всего проекта/аккаунта и автоматические резервные копии остаются отдельными задачами перед загрузкой конфиденциальных рабочих проектов.

## Откат

Переключить **только app** через compose предыдущего выпуска (`--no-deps --no-build --wait`), затем вернуть `current` на `20260927-pilot-access`. Персональный режим и Basic Auth должны остаться включены. Рабочий том не восстанавливать целиком: новая таблица feedback не мешает предыдущей версии; исходники, удалённые пользователем, не воскрешать откатом приложения. Исторические резервные копии остаются закрытыми для отдельного согласованного восстановления.
