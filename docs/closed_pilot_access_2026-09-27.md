## Граница доступа

- `ZARYA_PILOT_ENABLED=1` включает проверку всех HTTP-маршрутов перед роутерами/CORS. По умолчанию флаг выключен для совместимости текущего однопользовательского развёртывания.
- Без сессии доступны только страница/POST входа, статические ресурсы и healthcheck.
- Участнику доступны конкретные маршруты Studio и чтение нормативного радара. Новые маршруты автоматически не разрешаются.
- Архив YAML, прежний редактор, анализ чужих проектов, прямые файлы Wizard, публичные паспорта, OpenAPI и handoff участнику закрыты.
- Роль `admin` оставляет владельцу доступ к прежним маршрутам. Это доверенная роль, а не второй обычный участник.
- Проект, загрузки, предпросмотры: `ZARYA_STUDIO_DIR/_users/<user_id>/<draft_id>`. ID владельца берётся исключительно из серверной сессии. Старая cookie черновика не даёт прав и не присваивает старые данные.
- Файлы выпуска по-прежнему создаёт общий оркестратор. Доступ участника идёт только через Studio и сверяется с его текущим сохранённым комплектом. Публичный паспорт для участников пока недоступен.
- Текущий проект хранится в учётной записи и восстанавливается после входа с другого устройства. Сейчас поддерживается один текущий личный проект и переход в учебный пример/обратно, не многопроектная библиотека.
- Старые анонимные Studio-черновики остаются на месте. Автоматического присвоения любому вошедшему пользователю нет; безопасный перенос владельцу — отдельный согласованный шаг.

## Ключи и сессии

Обновление 29.09.2026: при включённом «Запомнить» новые сессии действуют до
30 суток без idle-таймера, не дольше ключа. Без галочки и для старых сеансов —
пределы из описания ниже. См. `docs/remember_device_2026-09-29.md`.

Персональный ключ — повторно используемый секрет приглашения, не одноразовая ссылка. По умолчанию действует 30 дней (допустимо 1–90). Создаётся криптографическим генератором, 256 бит случайности. Ключ не передаётся в URL и не хранится открытым в базе; используется SHA-256 случайного секрета, НЕ хеширование человеческого пароля.

Сессия: другой случайный токен, только его хеш в SQLite, `HttpOnly`, `Secure`, `SameSite=Strict`; максимум 7 дней и 12 часов бездействия, не дольше срока приглашения. Отзыв и перевыпуск ключа аннулируют все сессии участника, сохраняя проекты. На входе 20 попыток/15 минут с одного адреса, счётчик сохраняется между перезапусками.

Для изменяющих запросов проверяется источник, включая старые HTML-формы владельца. Межсайтовый CORS/предзапрос не даёт доступа. HTTPS обязателен; HTTP можно явно разрешить только для localhost через `ZARYA_PILOT_INSECURE_LOCAL=1` (не задаётся в compose).

Ориентир по устройству сессий: [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Это не сертификат безопасности и не замена независимого аудита.

## Администрирование (после согласования включения)

Обновление 28.09.2026: для новых приглашений используйте `/access/admin`, а не CLI;
там включается обязательное подтверждение условий автоархива. Общий Basic Auth
снят после проверки, добавлены отдельные рабочие проекты. Описание ниже —
история первоначального включения; актуально: `docs/pilot_admin_2026-09-28.md`.

CLI запускается из корня проекта с теми же `ZARYA_PILOT_DIR` и правами системного пользователя приложения. В контейнере путь уже задан: `/data/projects/_pilot`, в постоянном томе.

```sh
python -m scripts.pilot_access issue --name "Владелец" --role admin --days 30 --output /защищённый/путь/owner-key.txt
python -m scripts.pilot_access issue --name "Участник 1" --days 30 --output /защищённый/путь/tester-key.txt
python -m scripts.pilot_access list
python -m scripts.pilot_access revoke ID_УЧАСТНИКА
python -m scripts.pilot_access issue --name "Участник 1" --user-id ID_УЧАСТНИКА --days 30 --output /защищённый/путь/replacement-key.txt
```

Файл ключа создаётся с правами 0600 и не перезаписывается; ключ не печатается в stdout. Передавать его только конкретному адресату по согласованному приватному каналу. `--user-id` сохраняет личный проект при восстановлении доступа; для перевыпуска владельцу нужно явно сохранить `--role admin`. Это не почтовая рассылка и не публичная регистрация.

## Порядок включения и дальнейшего открытия пилота

1. Согласовать участников/роли и сохранить согласованную резервную копию тома; выполнить пробное восстановление. SQLite копировать при остановленном приложении либо штатным SQLite backup, не обычным копированием во время записи.
2. Подготовить учётную запись владельца. Старые данные не переносить и не удалять автоматически.
3. Включить `ZARYA_PILOT_ENABLED=1`, оставить текущий внешний Basic Auth на время проверки. Убедиться, что приложение получает HTTPS-схему от доверенного Caddy и порт 8000 не опубликован наружу.
4. Проверить реальным браузером вход владельца, вход двух участников, PDF/расчёт, повторный вход, отзыв и запреты старых адресов.
5. Только после этого отдельным согласованным изменением убрать общий Basic Auth, сохранив персональную защиту. Не раздавать участникам общий пароль вместо персональных ключей.
6. При откате сначала восстановить внешний Basic Auth/закрыть трафик участников, затем откатывать приложение. Нельзя просто выключить персональный флаг на открытом сайте.

Выполнено: две проверки восстановления, создание единственной учётной записи владельца, выдача ключа закрытым файлом на Mac, включение персонального режима за неизменённым Basic Auth. Вход/выход владельца проверены HTTP-запросами через доверенный внутренний proxy-hop; HTTPS снаружи без общего пароля возвращает 401. Два участника, загрузка PDF и генерация документов проверены только на изолированном серверном стенде, без рабочих документов. Снятие общего пароля и приглашение инженеров пока не выполнены.
