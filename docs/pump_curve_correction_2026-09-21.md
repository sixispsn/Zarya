# L02: согласованное исправление кривой насосной системы

Дата: 21.09.2026. Основание: «правим 2 пункт как считаешь нужным — хоть полностью».
Это разрешение на L02, не на L03/L04/L05 из аудита.

## Баланс и границы метода

Баланс требуемой добавки насоса: Hнас=max(0,Hgeom+ΣHпотерь+Hпр−Hгар).
Основание баланса: СП 30.13330.2020, п. 13.11, формула (19),
[официальный базовый PDF ФАУ ФЦС](https://api.faufcc.ru/api/assets/348e662a-c0ae-43ad-9ace-9c96309387b6).
Текст п. 13.11 дополнительно сверен с
[консолидированной публикацией](https://internet-law.ru/documents/prod/pravila/0/sp_30.html).
Это не заключение о соответствии всего подбора всем положениям СП.

Оценочная кривая сохранена квадратичной, но теперь согласована с балансом:

    H0 = Hgeom + Hпр − Hгар
    k = ΣHпотерь,расч / Qрасч²
    Hсист(Q) = max(0, H0 + kQ²)

Квадратичное масштабирование — явно обозначенная инженерная оценка, а не
дословная формула СП. Hгар и свободный напор приняты постоянными. Такая модель
не заменяет поучастковую гидравлику во всех режимах, расчёт регуляторов или
характеристику частотного регулирования. Исходные напоры должны относиться к
одной расчётной схеме и общей привязке отметок.

Контрольный пример: Q=5 м³/ч; Hgeom=25 м; ΣHпотерь=5 м; Hпр=20 м; Hгар=40 м.
Ранее график давал 42,5 м при требуемых 10 м. Теперь H0=5 м, k=0,2,
Hсист(5)=10 м — и в ядре, и в API, и в модели ПЗ, и на графике.

## Что изменено

- Общий `PumpSystemCurve` вместо разных формул в ядре и графике.
- H0 сохраняет знак: при Hгар=47 м получается −2+5=3 м, не 5 м.
- При достаточном Hгар — ветвь «повышение напора не требуется», без кандидатов.
  Проверка максимального давления остаётся отдельной задачей.
- Убраны подстановки 5/8 м потерь и k=0,1. Неизвестные потери нельзя считать нулём.
- Геометрия вводится явно либо оценивается по явно заданной этажности;
  прежняя оценка по этажам помечена как требующая проверки отметок.
- Промежуточные Q, H0, k и требуемый напор не округляются для построения кривой.
  Отображаемые числа форматируются отдельно.
- В В2 из единственной пары Q/H больше не строится выдуманная парабола.
  Показываются каталог при Qрасч и требуемая точка. Фактическое пересечение и
  регулирование остаются неподтверждёнными. Существующий строгий фильтр В2 по
  полному Q/H не изменён. Изменение ранжирования при таком сравнении ожидаемо:
  для 2,6 л/с и 70 м первый кандидат PFFS CDM10-8, Hкат=73,6 м при Q=9,36 м³/ч.
- Старые сохранённые результаты без версии кривой не получают новый график
  из старых коэффициентов: выводится требование пересчёта.
- PDF показывает отдельно расчётную точку и оценочную характеристику;
  кандидаты обозначены предварительными.

## Сверка с legacy

Исходный HTML не менялся, SHA-256:
`ace54b14e2f30fadaec768ec06aa5a326553709b9a869263208ef8ee58df3788`.

`scripts/legacy_pumps_reference.mjs` исполняет архивный код без записи в HTML.
По умолчанию воспроизводит прежнюю ошибку. Только явный флаг
`approved_l02_correction` заменяет формулу H0/k и ограничивает требуемую
добавку снизу нулём. Каталог, допуск, поиск и рейтинг JS не меняются.

`tests/test_pump_system_curve.py` проверяет равенство напоров в расчётной точке
на сетке 150 сочетаний Q/потерь/Hгар, отрицательную постоянную часть, нехватку
данных, достаточный напор, точность сериализации, API, мост ПЗ и SVG. Отдельно
12 сценариев (одиночный, параллельный, последовательный) сравниваются с JS при
явной поправке L02; неизменность архива проверяется SHA-256.

L03 (допуск недостаточного насоса) и L04 (конечные точки/поиск пересечения)
намеренно не исправлены. Их наличие явно указано в результате. Числа
предварительных кандидатов не являются подтверждением их пригодности.

## Состав выдачи

Изменён только расчётный лист насосов и соответствующая таблица основной ПЗ.
Проверен состав насосных данных по ГОСТ Р 21.619-2023, п. 5.1.8: Q/H,
характеристика, мощность, резерв, кавитационные/входные условия. Неизвестные
данные не заменены проектными решениями. Это приложение не заменяет всю ПЗ,
баланс по форме 2 или графическую часть. Их состав данной правкой не изменён.
