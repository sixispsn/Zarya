# Второй проход подготовки к комиссии: 14.09.2026

Область: почему не рассчитывается наполнение этажных ветвей и когда можно
использовать ранее рассчитанное h/d. Это не замена гидравлической методики,
не согласование инженерных решений и не положительный эталон проекта.

## Найденные программные дефекты

1. `assess_wastewater_diagnostics()` исключал этажные ветви из всего прохода,
   включая гидравлику. Поэтому даже явно заданные расход, уклон, геометрия
   трубы и коэффициент шероховатости не приводили к расчёту ветви.
2. ГОСТ-аудит сверял рассчитанное h/d с диаметром, уклоном и шероховатостью,
   но не с текущим расходом. Изменение нагрузки при прежней геометрии могло
   оставить устаревшее наполнение в статусе подтверждённого расчёта.

## Исправление и границы

- Ветви К1/К3 передаются существующему решателю Шези только с собственным
  явно заданным расходом. Общий расход здания или стояка не распределяется.
- Если не хватает расхода, уклона, n или источника n, диагностика перечисляет
  недостающие исходные данные вместо молчаливого пропуска. Из спецификационной
  суммарной длины не выводится длина одной ветви.
- Проверки линейного обслуживания магистралей не переносятся на этажные
  ветви. Расстановка прочисток, ревизий, тройников и геометрия схем не меняются.
- Аудит перечитывает расход из текущего проекта, в том числе из текущих
  нагрузок стояков, а не из кэша диагностики. Сравнение соответствует
  существующему округлению расхода в результате (три знака).
- Результат расчёта не записывается в исходный `fill_ratio`.
- К2 не подключён к критериям самоочищения бытовых стоков. Для водостоков
  требуется отдельный подтверждённый режим и профиль гидравлической проверки;
  признак PN не подтверждает напорный режим.
- Условия применимости, формулы, коэффициенты, округления существующего
  решателя, legacy В1/В2/Т3/Т4 и расчётные/визуальные эталоны не изменены.
  Ветвь, не прошедшая имеющиеся критерии решателя, не объявляется готовой:
  решение для нерасчётного участка требует отдельного обоснования, которое
  этот проход автоматически не создаёт.

## Что нужно от контрольного объекта

| Пробел | Подтверждённое состояние | Чем закрывать |
|---|---|---|
| Квартиры | `building.apartments = 0` | Число квартир из экспликации АР |
| Четыре ветви К1 | Нет индивидуальных расходов, n и источников n | Нагрузки ветвей и данные выбранных труб; после ввода существующий решатель теперь вызывается |
| К2-М1 и К2-Вып1 | Нет расходов участков, n и источников n; профиль расчёта К2 не подключён | Подтверждённый водосбор/расход и режим водостока, затем отдельная проверка применимости расчёта |
| К1-М1, 0-52 м | Прежнее замечание по доступу для обслуживания | План подвала и доступные точки обслуживания с привязками |
| План воды | Нет опорного плана от подключения до ввода | ТУ, опорный план и привязки, либо согласованная ссылка на смежный комплект |

Четыре блокирующие группы `demo/control_blockers.json` сохранены без правок.
Необходимые данные не заменены числами ради зелёного статуса. Для следующего
инженерного прохода нужен обезличенный жилой объект с АР и ТУ.

## Проверка документов

Состав проверяется существующими матрицами ГОСТ Р 21.619-2023 (включая
п. 5.1.21 и форму 2 баланса) и ГОСТ Р 21.620-2023 (пп. 5.1.3.3,
5.1.4.1, 5.1.6.1, 5.2.2-5.2.4). Это проверка состава, не утверждение полного
соответствия: неполный пример по-прежнему не допущен к выпуску.

При визуальном просмотре расчётного приложения обнаружено переполнение
колонки «Результат» и тесный заголовок допустимого расхода стояка. Ширины
колонок исправлены без уменьшения шрифта. Новый тест проходит реальную
печатную раскладку WeasyPrint и проверяет границы текстовых блоков внутри
каждой ячейки обеих таблиц; одних строк в HTML для такого контроля недостаточно.

- Полный прогон после исправления гидравлического конвейера: 1056 тестов,
  без ошибок (291 с).
- После добавления проверки перегруженной ветви и исправления таблиц:
  49 профильных тестов, включая контроль выпуска, ГОСТ-матрицы,
  неизменность графических эталонов и новую проверку печатной раскладки.
- Строгий mypy девяти релизных модулей, Ruff изменённых Python-файлов и
  `git diff --check` проходят.
- Контрольная сборка: 17 PDF, статус `blocked`, ровно четыре ожидаемые причины.
- Все семь страниц итогового расчётного приложения отрендерены и проверены
  визуально. Текст остаётся в ячейках, рамки и нумерация сохранены.
