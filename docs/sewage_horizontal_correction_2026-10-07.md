## Ошибка и нормативное основание

Рабочий legacy вычисляет `q_stok = tot.q_sec + 1.6`. Это формула (5) п. 5.5
СП 30.13330.2020 для стояков. Сама арифметика не исправляется.
Ошибка Python-интеграции: `section_main_hydraulics` использовал этот результат
для конечного горизонтального участка, а `resolve_k1_main_flows` суммировал
максимумы стояков. Такая сумма не является формулой (7).

Пункт 5.7: `q_sL = q_hr_tot / 3.6 + Ks * q0s`. Максимальный часовой расход
относится только к подключённым потребителям участка; не суточный расход / 24.
N - число подключённых приборов, не жителей. L по примечанию таблицы 5.1 -
от последнего стояка до ближайшего следующего присоединения, при его отсутствии
до ближайшего канализационного колодца. Общая длина разводки и длина на рисунке
не заменяют L. Наружная сеть здесь не моделируется.

Источник: загруженный пользователем официальный PDF
`SP-30.13330.2020-Vnutrenniy-vodoprovod-i-kanalizatsiya-zdaniy.pdf`,
печатные страницы 16-17 (PDF 25-26). SHA-256:

## Реализация и ограничения

- Единый новый модуль `app/calc/sewage_horizontal.py`, 169 точных ячеек таблицы.
  Первоначально промежуточные N/L оставались без автоматического результата.
  По последующему отдельному согласию пользователя 07.10.2026 добавлена
  интерполяция внутри таблицы (описана ниже). Экстраполяция, округление N/L
  под таблицу и скрытая подстановка Ks=1 по-прежнему запрещены. Ручной расход
  допускается только с явным источником расчёта.
- Studio: расчёт конечного участка по текущему максимальному часовому расходу
  здания, отдельного участка по его часовому расходу либо готовый ручной расход.
  Для автоматического расчёта нужны N и L; q0s всего здания перечитывается из
  текущих исходных, для отдельного участка задаётся отдельно.
- Часовой расход из канонического `calculate_water_demand` используется с его
  опубликованной точностью (3 знака). Внутри формулы (7) промежуточного округления
  нет; решатель Шези получает полный результат, его вывод традиционно до 3 знаков.
- Сеть: расход каждого горизонтального участка считается отдельно. Никакой суммы
  стояков или передачи максимума в следующую трубу. Поля запроса, YAML и Project
  хранят отдельные исходные `q_hour_max_m3h`, `fixtures_count`,
  `receiving_length_m`, `fixture_max_lps` и `flow_source` для ручного расхода.
- Объявленные напорные линии насосной подсистемы не рассчитываются по формуле (7)
  и не проверяются решателем самотёка. Их отдельный насосный расчёт не меняется;
  одна только прочность материала PN не подтверждает напорный режим.
- Старый ручной расход без основания и прежний кэш не считаются подтверждёнными.
  ПЗ/расчётный лист повторно вычисляют диагностику. Версии расчёта и выдачи Studio
  обновлены: старые PDF не предлагаются как актуальные; архив не удалён.
- Принципиальный разрез остаётся доступен без точного N/L; гидравлическая проверка
  отсутствующих данных не утверждается. DN/i автоматически не меняются.
- В старом двухэтажном примере 9 м подвала не являются L до колодца. Без отдельного
  L снят прежний необоснованный вывод о самоочищении К1; К2 не меняется.
- Обе копии legacy, расчёты В1/В2/Т3/Т4, суточный баланс и формула (5) сохранены.
  Это отдельное согласованное расширение, не заявление о паритете формулы (7)
  с отсутствующей в HTML методикой.

## Согласованная интерполяция Ks, 07.10.2026

Пользователь отдельно разрешил линейную интерполяцию после обсуждения:
пункт 5.7 отсылает к таблице 5.1, но сама таблица не содержит прямого указания
на способ обработки промежуточных значений. Реализация не выдаёт выбранный
способ за дословное требование СП или гарантию приёмки экспертизой.

Для N0 <= N <= N1 и L0 <= L <= L1 вычисляются доли
`t=(N-N0)/(N1-N0)` и `u=(L-L0)/(L1-L0)`. Сначала выполняется линейная
интерполяция по L в каждой из двух соседних строк, затем по N между
результатами. Эквивалентная формула:

`Ks=(1-t)(1-u)K00 + (1-t)uK01 + t(1-u)K10 + tuK11`.

Если одна координата совпадает с табличной, интерполируется только другая;
при совпадении обеих возвращается точное табличное значение без интерполяции.
Неравномерные интервалы осей не заменяются индексами строк/столбцов. N остаётся
целым числом, L может быть дробным. Промежуточное округление Ks/Q отсутствует.
В расчётной таблице Ks показывается до шести знаков; вывод не меняет расчёт.

Границы: 4 <= N <= 1000; 1 <= L <= 1000 м. Выход за любую границу, NaN,
бесконечность, логические значения и дробное N отвергаются. Недостающие N/L
не восстанавливаются из количества жителей, длины рисунка или всей магистрали.
Округление сразу N и L вверх не обеспечивает запас: Ks растёт с N, но
уменьшается с L. Интерполяция сохраняет введённые данные; это не утверждение
о точности физической модели между табличными точками.

Контрольные числа, не исходные Самары:

- N=33, L=8,5: опорные Ks 0,50 / 0,47 / 0,51 / 0,47 при N=32/36,
  L=7/10; Ks=0,48625. При qчас=1,268 м³/ч и q0s=1,6 л/с
  q_sL=1,130222222… л/с, вывод 1,130.
- N=572, L=10: Ks=0,8744 между N=500/1000; при qчас=7,71 м³/ч
  и q0s=1,6 л/с q_sL=3,540706666… л/с. Это контроль алгоритма,
  не подтверждение числа приборов или расстояния до колодца на объекте.
