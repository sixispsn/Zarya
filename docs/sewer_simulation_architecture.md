# Движок движения стоков: архитектура сетевого этапа

## 1. Граница расчёта

Движок решает две связанные, но раздельно трассируемые задачи:

1. Гидравлика самотечного участка: `Q`, `V`, `h/D`, живое сечение и
   пропускная способность по уравнению Шези в форме Маннинга.
2. Сценарный прогноз осадка: баланс массы взвешенных веществ с уменьшением
   живого сечения во времени.

Расчёт гидравлики является инженерным расчётом. Прогноз миллиметров осадка не
является нормативной константой: он требует концентрации взвесей, объёмной
плотности осадка, эффективности осаждения и источника калибровки.

Таблицы Шевелева в Zarya пока не оцифрованы. Поэтому текущий решатель честно
обозначен как Шези-Маннинг, а не как табличный расчёт «по Шевелеву». Позже
табличный адаптер можно добавить как второй `HydraulicSolver` и проверить
golden-тестами на контрольных строках источника.

## 2. Слои системы

### Входные данные

- `PipeSectionConfig`: ID, длина, внутренний диаметр, уклон, материал, `n` и
  источник шероховатости, `V_min` и его источник, порог критического наполнения.
- `PipeSectionState`: накопленная вода, толщина осадка, уже вышедший за границы
  трубы объём.
- `NetworkNode` (следующий динамический этап): отметка лотка, площадь хранения
  в колодце/приёмнике, допустимый уровень, тип границы.
- `NetworkEdge`: направленная связь «участок -> узел -> следующий участок».
- `InflowHydrograph`: внешний расход и концентрация взвесей по времени.
- `OutletBoundary`: явно заданный свободный выпуск либо предел расхода. Уровень
  наружной сети потребует динамического решателя следующего этапа.
- `FixtureSafetyInput`: абсолютные отметки подключения и перелива прибора,
  фактическая глубина и минимальный остаток гидрозатвора.
- `FirstManholeBoundary`: только отметка лотка и сценарный уровень воды первого
  колодца; наружная сеть при этом не моделируется.
- `TrapPressureHydrograph`: давление канализационного воздуха относительно
  атмосферы у гидрозатвора.

Без отметок узлов и граничного уровня наружной сети движок может выявить
недостаточную пропускную способность, но не имеет права утверждать фактическую
отметку подпора или затопления.

### Расчётные компоненты

- `PipeSection` - локальная геометрия, Шези-Маннинг, хранение воды и осадка.
- `HydraulicSolver` - нормальная глубина и расходная характеристика участка.
- `SedimentTransportModel` - масса поступивших и осевших взвесей.
- `SewerNetworkSimulator` - реализован: шаг времени, баланс объёма и взвесей,
  передача воды по направленному графу, гидрограф и выходные границы.
- Кинематический подпор - реализован: непринятый нижним участком объём остаётся
  в верхнем участке и последовательно заполняет сеть против направления стока.
- `BackwaterSolver` по отметкам и уравнениям Сен-Венана - следующий этап.
- `SimulationEventLog` - следующий слой хранения истории смены статусов.

## 3. Геометрия и гидравлика участка

Для чистой трубы при наполнении `h` вычисляются площадь `A`, смоченный периметр
`P` и гидравлический радиус `R=A/P`. Далее:

```text
C = R^(1/6) / n
V = C * sqrt(R * i) = R^(2/3) * sqrt(i) / n
Q = A * V
```

При наличии осадка его верх принят горизонтальным. Из полного кругового
сегмента воды вычитается сегмент осадка; в смоченный периметр включаются стенка
трубы и граница «вода - осадок». Это точнее равномерного уменьшения диаметра.

Расходная характеристика круглой трубы имеет максимум до полного наполнения.
Поэтому движок хранит отдельно:

- `maximum_gravity_capacity_lps` - максимум безнапорной характеристики;
- `full_section_capacity_lps` - значение при заполнении доступного сечения.

Превышение первого значения запускает накопление воды. Оно ещё не называется
затоплением, пока баланс объёма не покажет выход воды за физический объём трубы
и узла.

## 4. Осадок

Для шага `dt`:

```text
deficit = max(0, 1 - V / V_min)
capture = eta_0 * deficit^p
M_in = Q * dt * C_ss
M_deposit = M_in * capture
V_deposit = M_deposit / rho_bulk
```

Новый объём осадка распределяется по длине участка и преобразуется в глубину
кругового сегмента. При `V >= V_min` осаждение на этом шаге равно нулю.

Эрозия осадка пока не включена. Для неё нужны критическое касательное
напряжение, гранулометрия и коэффициент размыва; без этих данных «самоочистку»
нельзя превращать в произвольное уменьшение слоя.

В качестве исходного сценария, заданного пользователем, разрешены только:

- внутренний диаметр 100-110 мм: `V_min = 0,6 м/с`;
- внутренний диаметр 150-200 мм: `V_min = 0,7 м/с`.

Для иных диаметров значение должно быть введено явно. Интерполяции нет.

## 5. Один шаг сетевой симуляции

1. Проверить ориентированный граф, отметки и граничные условия.
2. Получить внешние притоки на интервале `[t, t + dt]`.
3. Зафиксировать состояние всех участков на начало шага.
4. По уравнению неразрывности передать объём из ячеек/участков в следующие
   узлы. Расчёт должен быть консервативным: вход = выход + изменение хранения +
   затопленный объём.
5. Ограничить отток текущей расходной характеристикой с учётом осадка.
6. Оставить непринятый объём в верхнем участке. При превышении физического
   объёма трубы зарегистрировать затопление. Фактическая отметка выхода воды
   появится только после ввода геометрии узлов.
7. По фактически прошедшему расходу обновить массу и геометрию осадка.
8. Сформировать снимок каждого участка и события шага.

Для явной схемы шаг выбирается по условию Куранта. Если один участок слишком
длинный, он делится на расчётные ячейки; иначе поток не должен «перепрыгивать»
несколько длин трубы за один шаг.

## 6. Статусы и выдача

На каждом шаге по каждому участку выдаются:

- время, входящий и выходящий расход;
- `V`, `h/D`, доступное наполнение после осадка;
- толщина и масса осадка;
- запас пропускной способности;
- накопленный и затопленный объём;
- основной статус и все активные флаги.

Приоритет основного статуса: `Затопление` -> `Критическое наполнение` ->
`Заиливание` -> `Норма`. Все одновременные причины сохраняются в
`active_flags`, поэтому риск заиливания не теряется при высоком наполнении.

### Подпор и гидрозатворы приборов

Для каждого открытого приёмника стоков выполняются две отдельные проверки.

Статический подпор первого колодца:

```text
H_backwater = max(0, Z_manhole - Z_connection)
margin = Z_overflow - Z_manhole
```

- `Z_manhole <= Z_connection` - статический подпор до прибора отсутствует;
- `Z_connection < Z_manhole < Z_overflow` - подпор дошёл до прибора;
- `Z_manhole >= Z_overflow` - вода достигает открытого перелива, фиксируется
  подтопление через этот прибор.

Проверка гидрозатвора:

```text
delta_h_mm = delta_p / (rho * g) * 1000
remaining_seal = seal_depth - abs(delta_h_mm)
```

Отрицательный перепад может вызвать сифонный срыв, положительный -
выдавливание. Гидростатический напор воды со стороны выпуска добавляется к
давлению канализационного воздуха. Если воздушный перепад не рассчитан и
одного гидростатического напора недостаточно для однозначного вывода, результат
помечается как требующий данных, а не как безопасный.

Сетевой статус `Затопление` без геометрии узла показывает перегрузку участка,
но не назначает произвольно место выхода воды. Подтопление конкретного прибора
подтверждается только достижением его абсолютной отметки перелива.

## 7. Реализовано и следующий этап

Реализованы `PipeSection` и `SewerNetworkSimulator`: кусочно-постоянный
гидрограф, ориентированный граф без циклов и разделения потока, свободная или
ограниченная выходная граница, условие Куранта, консервативные балансы воды и
взвесей, осадок и кинематическое распространение ограничения вверх по сети.
Также реализована проверка внутренних приборов по уровню первого колодца и
проверка гидрозатворов по заданному графику перепада давления.

Каждый введённый участок сейчас является одной расчётной ячейкой. Для длинного
участка проектировщик должен разделить трассу либо уменьшить `dt`; нарушение
условия Куранта останавливает расчёт.

Следующий уровень точности - узлы с отметками, объёмами и допустимыми уровнями,
а затем динамический волновой решатель по уравнениям Сен-Венана. Он нужен для
расчёта отметки подпора от наружной сети, режима заполненной трубы и места
фактического выхода воды. До этого движок выдаёт объём перегрузки и участок
риска, но не выдумывает отметку затопления.

Отдельный последующий слой для стояков должен вычислять сам
`TrapPressureHydrograph` по расходу, диаметру и высоте стояка, конфигурации
вентиляционной части и одновременности сбросов. Пока перепад давления является
явным входом с источником.
