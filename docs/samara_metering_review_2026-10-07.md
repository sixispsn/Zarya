# Самара: водомеры и происхождение количеств

## Комплекты общедомовых водомеров, 09.10.2026

СО учитывала два общих счётчика и по одному счётчику ХВС/ГВС, но
присоединительный комплект был только у общих. Добавлены отдельные строки
`meter_cold_kit` / `meter_hot_kit`: один комплект на один счётчик ветви,
без умножения на количество вводов. В Самаре теперь **2 комплекта DN50
на вводах + 1 DN32 ХВС + 1 DN32 перед водонагревателем**.

Единый подбор в `app/pz/metering_accessories.py` проверяет точный ID модели,
наружную резьбу корпуса, резьбу присоединения к трубе, статус размеров,
наличие источника и актуальность каталога. Автоматическое предложение
включено только в принятом режиме `catalogue_proposal`. Несовместимый
явно заданный комплект, устаревший каталог и неоднозначный кандидат не
заменяются удобным значением; остаётся неподтверждённое требование.
Общий комплект не копируется на другую модель ветви. Подбор квартирных
комплектов использует ту же проверку, количества квартир не менялись.

Два конца `kit_in` / `kit_out` принадлежат одной строке СО: два символа
не создают два комплекта. В примечании указано не закупать его повторно,
если он входит в поставку счётчика. Это условие комплектации, а не
подтверждение состава поставки изготовителя. Справочные L1 из существующего
каталога показаны на листах ВУ, но не подменяют монтажную длину узла,
прямые участки либо метраж труб. Каталог не расширялся новыми изделиями.

Новый срез: **116 позиций / 80 с количеством / 36 без количества**,
восемь из 80 остаются оценочными. Семь неизвестных количеств ВУ не закрыты
этой правкой: опоры, четыре роли труб, прочая фасонина и уплотнение требуют
монтажных исходных. Новых блокировок принципиальной схемы нет.

Контроль: 363 профильных теста с рабочим legacy; сквозной прогон
`scripts/check_samara_document_consistency.py`, включая проверку 2+1+1
и отсутствия двойного учёта. PDF/аудит — `output/pdf/samara-meter-node-kits/`.
СО 18 страниц, ВУ 4; ИОС2/ИОС3 54/13. Все страницы СО/ВУ просмотрены,
новые строки отдельно проверены в увеличении. Состав/оформление ВУ
сопоставлены с п. 5.2.2.6 и приложением Г пользовательского ГОСТ Р
21.619-2023; баланс по п. 5.1.21 остаётся прежним отдельным листом.
Это не подтверждение полноты исходных или готовности к экспертизе.
Расчётные результаты прежние, кроме отчёта заполненности СО; ПЗ,
основные схемы ИОС2 и все страницы ИОС3 совпадают по растру с предыдущими.
Исходный Project и обе копии legacy неизменны. Studio и PDF используют
версию `2026-10-09-meter-node-kits`, чтобы старые выдачи не оставались
актуальными. Прогресс 65%, на сервер не публиковалось.

## Проверка количеств в Studio, 09.10.2026

`app/pz/spec_quantity_review.py` читает результат `build_water_specification`,
ничего не меняет в Project, строках СО и инженерных расчётах. Общая точка
использования — обычный расчёт Studio и фиксированный пример Самары.
При доменной ошибке СО выводится «проверка не выполнена», а не пустой
успешный отчёт; расчёт расходов не отменяется. Проверки выпуска сохранены.

Текущий срез Самары: **114 позиций / 78 с количеством / 36 без количества**.
Восемь из 78 — оценки, а не подтверждённый метраж. Отсутствующие количества:

- В1 — 3 строки: арматура стояков, метры ввода и масса заделки;
- водомерный узел — 7: опоры, четыре отрезка труб, прочая фасонина и заделка;
- В2 — 10: обвязка/сервис станции, количества диафрагм вне модельных стояков,
  масса огнезащитной заделки;
- Т3/Т4 — 16: насос/арматура циркуляции, стояковая арматура, фасонина,
  крепления/гильзы, трубы/изоляция и заделка.

Числа не зашиты в интерфейс: группа и позиция берутся из актуальной СО.
Строки без единицы измерения считаются текстовыми требованиями отдельно.
Неизвестное количество не заменяется нулём. Отрицательное, бесконечное,
нечисловое или дробное количество в штуках отмечается ошибкой; явный ноль
остаётся нулём. Заполненность не подтверждает гидравлику, паспорт или закупку.

Блок по умолчанию свёрнут и не добавляет запретов на предпросмотр схемы.
В обычном проекте можно перейти прямо к существующим полям числа стояков
или квартирных узлов. Самара как фиксированный пример остаётся без таких
кнопок. При редактировании исходных отчёт отзывается вместе с расчётом;
версия Studio поднята до `2026-10-09-spec-quantity-review` для обновления
ранее сохранённых расчётов. Версия PDF не изменена.

Контроль: 192 профильных Python-теста, включая рабочий legacy, и 16 JS-тестов.
Браузером проверены свёрнутый/раскрытый вид, отсутствие редактирования Самары,
переход к стоякам с фокусом первого поля, пересчёт синтетического проекта
после ввода 4/4/2 стояков: 40 → 36 неизвестных позиций (метры не заполняются).
На узком экране ширина документа равна ширине окна, горизонтального overflow нет.
Скриншот: `output/ui/spec-quantity-review/studio-samara.png`.
Project Самары и обе копии legacy не менялись; нового комплекта PDF нет.
Прогресс остаётся 65%, публикации в этом заходе нет.

## Конкретные присоединения PE-X, 09.10.2026

Обычная СО Studio теперь предлагает для текущей PE-X 20×2 пару
**VT.4410.NE.20 + VTr.580.NE.040E**, по отдельной позиции на каждое изделие.
Каталог ограничен этим проверенным сочетанием. Подбор выполняет сама ЗАРЯ
по текущему материалу, Dн×s, температуре и двум парам присоединений:
труба/фитинг → евроконус → обычная G1/2 арматуры. Не требуется вмешательство
ассистента или ручное присвоение артикулов контрольному Project.

В Самаре на каждую систему В1/Т3: 143 фитинга + 143 переходника перед краном
и столько же после обратного клапана. Итого 286 фитингов и 286 переходников
на систему; прежние общие требования этих концов заменены, а не добавлены
поверх. 143 комплекта счётчика, 143 ниппеля кран–фильтр и 98 фильтр–РД
не изменились. Количества по принятому типовому узлу, не по обмеру квартир.

В `app/data/apartment_pipe_connections.py` зафиксированы источники:

- [VALTEC ПС 47657-2](https://valtec.ru/document/technical/fitingi-collectornye-1125.pdf),
  стр. 1–2: применение для ХВС/ГВС, PE-X, точный артикул 20×2,
  PN=1,0 МПа, диапазон −20…110 °C. SHA-256
  `1bb98d42edf11b1e845ab7fde1738f79229c8698d633ebb79bdbdac19b02ceca`.
- Тот же паспорт, п. 6.4: подтяжка накидных гаек каждые 6 месяцев.
  Поэтому доступность соединений — обязательное ограничение предложения,
  оно не означает разрешения замоноличить обжимной узел.
- [VALTEC ПС 47639-4](https://valtec.ru/document/technical/VTr-1025.pdf),
  стр. 8–9: VTr.580.NE.040E, 3/4 ЕК × 1/2.
  SHA-256 `44e8069b8d2e0660acd4e1ca60a2e4f9b42c047db86bf31bafc22ca1a76be6f6`.
- [Чертёж VTr.580.NE](https://valtec.ru/document/technical/drawing/VTr.580.NE/VTr.580.NE.pdf):
  длина 25,5 мм против A=26 мм в паспорте. SHA-256
  `cca90a034487f125b74dacd04f46bbb9e12cf791adf04de5c8a9d84e2e9b12f1`.
  Расхождение не усредняется; подтверждённая монтажная длина не выдаётся.

Обычная G3/4 не считается ответной частью евроконуса. PE-X 20×2,8,
металлополимер, неизвестная геометрия, несовместимые порты, неподходящая
температура, изменённый источник или неоднозначный каталог не получают
этот артикул. Остаётся одна строка требования без подобранной модели;
Т3 не заимствует трубу В1. Серия трубы, P/T всего узла и монтажная
компоновка остаются неподтверждёнными; это кандидаты, не готовность к закупке.

Контроль: 336 профильных тестов с рабочим legacy; обычный HTTP-путь Studio;
все 17 листов СО просмотрены после рендеринга. ИОС2/ИОС3 — 52/13 страниц.
Первые 35 листов ИОС2 и все 13 ИОС3 совпадают по растру с предыдущей выдачей,
расчётные результаты и хэш модели совпадают. Баланс, сведения об учёте,
графическая часть по ГОСТ Р 21.619-2023 не заменены деталировкой СО;
ИОС3/ГОСТ Р 21.620-2023 содержательно не изменён. Обе копии legacy сохранены.

## Присоединения квартирных узлов, 07.10.2026

В `app/pz/apartment_connections.py` введён отдельный слой требований
присоединений, используемый обычной спецификацией Studio. Он не изменяет
гидравлику, подбор водомеров или состав принципиальных символов.

Для каждой системы В1 и Т3 в Самаре:

- 143 присоединения трубы перед краном и 143 после обратного клапана;
- характерная подводка PE-X 20×2, требуемый резьбовой конец G1/2 НР;
- 143 ниппеля между краном и фильтром;
- ещё 98 между фильтром и РД, только по принятой ведомости этажей 1–11;
- прежние 143 комплекта счётчиков, без повторного учёта их штуцеров/гаек.

Это количество по принятому типовому составу квартирного узла, не обмер
всех квартир. Неизвестное количество РД не заменяется общим числом квартир.
Пара наружная/внутренняя G одного размера не получает лишний ниппель;
неизвестная, несовпадающая либо неподдерживаемая пара остаётся требованием
без артикула. Минимальный каталог ниппелей ограничен G1/2 и G3/4.
Без счётчиков и вне поддерживаемой квартирной композиции новые строки
не добавляются. Т3 не заимствует геометрию из В1.

### Источники и ограничения

- [VALTEC VTr, ПС 47639-4](https://valtec.ru/document/technical/VTr-1025.pdf),
  стр. 2 и 9: G, наружная/наружная, артикулы VTr.582.N.0004/.0005.
  SHA-256 `44e8069b8d2e0660acd4e1ca60a2e4f9b42c047db86bf31bafc22ca1a76be6f6`.
- [Габаритный чертёж VTr.582.N](https://valtec.ru/document/technical/drawing/VTr.582.N/VTr.582.N.pdf):
  у DN15 A=25 против 23 мм в паспорте; у DN20 S=26 против 27 мм.
  Поэтому размеры не допущены к монтажной компоновке. Модели в СО —
  предварительные кандидаты по резьбе, не проверенная монтажная цепочка.
- Паспорт ДЕКАСТ ВСКМ 90, ред. 1.06, рис. 1, табл. 6–7:
  комплект учитывается один раз; L1 справочный, зависит от исполнения.
  Наружную резьбу обычного VTr нельзя использовать вместо поверхности
  уплотнения накидной гайки с плоской прокладкой (п. 2.3 паспорта VTr).

Для PE-X 20×2 не задана фирменная соединительная система и способ монтажа.
Артикул перехода к трубе оставлен открытым; равенство наружного диаметра
не подтверждает совместимость с фитингом для 20×2,8. Рабочий материал и
гидравлический внутренний диаметр не менялись. Ни длины прямых участков,
ни полная монтажная длина, ни P/T-работоспособность узла этим шагом не
подтверждены. Раздел не означает полной готовности СО к закупке.

## Исправленная связка

Фиксированный пример загружал старый DTO с ручным режимом водомеров без
моделей. Обычный Studio уже включал предложение каталога. Теперь оба пути
используют `studio_metering.catalogue_proposal` до построения Project.
Сохранённые ручные назначения имеют прежний приоритет. Предложение означает
горизонтальный монтаж шкалой вверх, а не принятую закупочную комплектацию.
Каталог и политика включены в снимок примера; старый предпросмотр отзывается.
Исходный подписанный JSON Самары и результат В2 не изменены.

ДЕКАСТ ВСКМ 90 ДГ: общий ввод DN50, ответвления ХВС и перед нагревателем DN32.
Потери по принятому расчёту СП остались 1,451 / 3,479 / 4,703 м.
Паспортные Qmin класса B: 0,45 / 0,12 / 0,12 м³/ч; корпус 300 / 260 / 260 мм.
Паспортная граница Δp ≤ 0,1 МПа при Qmax не преобразуется в точную h(Q).
Сохраняются ограничения P/T, присоединений, прямых участков и времени выше Qn.

## Минимальный расход здания

В «Подключение и ТУ» добавлена свёрнутая необязательная группа «Водомеры ·
проверка минимального расхода». Для каждого узла отдельно задаются м³/ч и
основание. Это не паспортный Qmin, не средний расход и не максимум.
Пустые/частичные данные не закрывают проверку; явный ноль сохраняется и
даёт отрицательный результат при положительном паспортном минимуме.
Изменение DN повторно проверяет текущую модель, старый зелёный статус не
переносится. Изменение ответов отзывает PDF обычным механизмом Studio.
Самаре минимум не придуман. Предварительный PDF доступен, выпуск не разрешён.

## Спецификация

По текущей схеме: два вводных счётчика DN50 и по одному DN32 на ответвлениях.
Присоединительные комплекты: два комплекта, не четыре (две детали входят
в один комплект). В строках ВУ показано основание количества: состав одного
узла × число узлов. Метры ВУ по размерам SVG не вычисляются.

Контрольная ИОС2 содержит 99 позиций; 45 без количества. Восемь строк имеют
основание `area_estimate`: три группы труб В1, три группы креплений и две
группы изоляции. Прежняя оценка сохранена и не выдана за обмер.
Остальные строки нельзя автоматически считать проверенными только потому,
что количество присутствует: отдельно нужны границы исходной сети и состав
изделий. Количество квартирных узлов не равно автоматически числу квартир,
а длина диктующего пути не равна метражу сети.

## Следующий локальный шаг: квартирные узлы

Обычный Studio получил три необязательных поля в свёрнутой группе
«Потребители → Квартирные узлы · для спецификации». Выбор:

- неизвестная схема: количества остаются пустыми;
- по одному узлу ХВС и ГВС на квартиру: используется текущее число квартир;
- отдельное общее число узлов ХВС и ГВС: допускаются разные количества,
  несколько вводов в квартиру и явный ноль; пустое поле не равно нулю.
