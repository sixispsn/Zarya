# Заря

Инженерный калькулятор внутреннего водоснабжения и канализации по СП 30.13330.2020. Рассчитывает водопотребление, В1, В2, Т3/Т4, водоотведение, водостоки, водомеры, теплоизоляцию и насосные установки; формирует комплект документов стадии П.

## Безопасные исходные данные

Новый проект открывается без демонстрационных жителей, параметров здания,
значений ТУ и расчётной схемы В2. Учебный объект загружается только отдельной
кнопкой и маркируется как пример. В автоматическом режиме В2 проектировщик явно
выбирает строку таблицы 7.1 СП 10.13130.2020; общественное здание больше не
подменяется офисной категорией. Геометрия помещений и сети В2 участвует в
расстановке и гидравлике только после подтверждения, что она введена по плану
АР или расчётной схеме.

## Каталог насосов

Проектный подбор использует неизменённый архивный каталог legacy и отдельное
актуальное расширение. В расширение включены Wilo Helix FIRST V и проверенные
по каталогам 2025 года серии CNP/Aikon: повысительные установки PBS, пожарные
установки PFFS и циркуляционный in-line насос TD. Для PFFS/PBS используется
кривая одного рабочего агрегата; резервный насос не суммируется с рабочим.
Точные Q-H таблицы и зависящие от расхода NPSHr взяты из каталога базовых
CDM/CDMF; кавитационная проверка выполняется в рабочей точке. Источники,
страницы и SHA-256 зафиксированы в
[`docs/catalogs/cnp_2025.md`](docs/catalogs/cnp_2025.md).

## Zarya Proof

На экране готового комплекта работает «Рентген проекта». Расходы, напоры,
водомеры, насосы, решение по В2 и границы стадии П/Р раскрываются в цепочку:
исходные данные → норматив → штатный расчёт → принятое решение → документы.
Доказательный граф можно скачать в JSON. Слой Proof не меняет расчётное ядро
и отдельно контролирует совпадение расходов со штатным legacy-алгоритмом.

Кнопка «Что изменится?» выполняет несохраняемый расчёт альтернативных исходных
данных и показывает сравнение «было → станет» вместе с перечнем затронутых
документов. Предпросмотр использует тот же расчётный конвейер, но не создаёт PDF
и не изменяет сохранённый проект.

## Zarya Defense

Кнопка «Защитить проект» открывает полноэкранный режим работы с комиссией.
Любое решение раскрывается до исходных данных, нормативной ссылки, расчёта и
фактических PDF текущего выпуска. Если в документе найден сильный маркер
решения, встроенный просмотр открывает его сразу на соответствующей странице.

Вопрос комиссии сопоставляется только с существующим доказательным графом, без
генерации новых формул или нормативных выводов. По выбранному решению
формируется отдельный PDF-протокол с вопросом, ответом, доказательной цепочкой,
страницами документов и отпечатками проекта, legacy-эталона и сборки.
Встроенный режим WHAT IF повторно запускает штатный расчётный конвейер и
показывает влияние альтернативных исходных данных, не сохраняя их в проект.

Каждый успешный выпуск автоматически получает постоянный цифровой паспорт.
В постоянный том копируются фактически сформированные PDF, их полные SHA-256 и
запечатанный манифест доказательств. Read-only ссылка имеет непрогнозируемый
идентификатор, защищена общей авторизацией сайта и сохраняется после обновления
или перезапуска контейнера. QR-код ссылки включается отдельным листом в ПЗ,
в паспорт нормативного контроля и в ответы эксперту. При изменении любого
сохранённого файла экран паспорта показывает нарушение целостности и блокирует
выдачу повреждённого PDF.

## Анализ проекта-аналога

Раздел `/wizard/analyze` принимает текстовые PDF или ZIP с проектом,
расчётами, спецификацией, схемами и заключением экспертизы. Детерминированный
разбор:

- классифицирует документы и отмечает PDF без текстового слоя как требующие OCR;
- извлекает расходы, напоры, рабочие точки насосов, системы и нормативные ссылки;
- связывает каждый показатель с исходным PDF, страницей и коротким фрагментом;
- показывает разные значения между документами как предмет инженерной сверки;
- отмечает известные прежние редакции СП, не подменяя ими действующие нормы.

Проекты-аналоги и отчёты хранятся в каталоге проектов. Полный извлечённый текст
в JSON-отчёт не записывается. Загруженный проект не меняет алгоритмы В1, В2,
Т3/Т4, К1 и К2 и не считается нормативным эталоном автоматически.

## К1 и К2

- Расход К1 считается по принятому legacy-алгоритму; `q₀s` остаётся явным
  исходным параметром.
- Характерные стояки К1 проверяются только по точным узлам приложения К
  СП 30.13330.2020. Интерполяция таблиц и автоматическое распределение общего
  расхода между стояками запрещены.
- Для К2 воспроизведён legacy-расчёт дождевого расхода и добавлены проверки
  числа и шага воронок, паспортной способности, DN стояка и суммарной
  пропускной способности по пп. 21.5–21.12 СП 30.
- Трубы попадают в спецификацию только по явно заданным наружному диаметру,
  толщине стенки и длине. Горизонтальная гидравлика без аксонометрии
  маркируется как работа стадии Р.
- Приборы, ревизии, прочистки, противопожарные муфты, воронки и прочие
  штучные позиции задаются единым реестром `sewage.elements`. Он одновременно
  формирует спецификацию и векторную принципиальную схему А1 по составу
  п. 5.2.2.4 и примеру приложения В ГОСТ Р 21.620-2023; отсутствующие
  элементы программа не дорисовывает и не досчитывает.
- Канализация выпускается самостоятельным подразделом ИОС3:
  `ПЗ_К1_К2.pdf` по пункту 18 ПП РФ № 87,
  `Расчеты_К1_К2.pdf`, `Схема_К1_К2.pdf`,
  `Спецификация_К1_К2.pdf` и единый `Комплект_К1_К2.pdf`.
  Расчётное приложение К1/К2 также добавляется в конец общей ПЗ.

## Запуск для проверки

Требуются Python 3.12 и доступ в интернет при первом запуске. Само приложение работает локально: данные не отправляются на внешний сервер.

- macOS: распаковать архив и открыть `Запустить Зарю.command`. Если macOS заблокирует загруженный файл, открыть его через правый клик → «Открыть».
- Windows: распаковать архив и открыть `Запустить Зарю.bat`.
- После подготовки окружения браузер откроет `http://127.0.0.1:8000/wizard` автоматически.
- Для остановки закрыть окно запуска или нажать `Ctrl+C`.

Первый запуск устанавливает зависимости и поэтому занимает дольше последующих. Проекты сохраняются только на компьютере проверяющего в `~/.zarya/projects`.

## Запуск для разработки

```bash
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python start_zarya.py
```

Тесты:

```bash
pytest -q
```

## Размещение на сервере

Для VPS подготовлены Docker Compose, автоматический HTTPS и защита сайта
логином с паролем. Пошаговая инструкция находится в
[`deploy/README.md`](deploy/README.md). Пароль не хранится в репозитории:
на сервер записывается только его bcrypt-хеш, а сам пароль следует сохранить
в менеджере паролей.

## Сборка архива для передачи

```bash
python scripts/build_review_package.py
```

Готовый ZIP появляется в папке `dist`.
