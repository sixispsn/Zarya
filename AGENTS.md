# Обязательные правила расчётного ядра Zarya

## Общее правило оформления документов

По прямому указанию пользователя 14.10.2026 блоки сведений оформляются либо
полноценной таблицей (замкнутые внешние границы, горизонтальные границы строк
и вертикальные разделители граф, включая шапку и продолжения), либо обычным
текстом без декоративных горизонтальных разделителей и подчёркиваний.
«Полутаблицы» из текста с одними горизонтальными линиями запрещены.
Правило не отменяет нормативные полки линий-выносок, размерные линии,
штампы и другие собственно графические элементы чертежа.

«Позиции на узле» оформляются отдельным текстовым списком.

## Расчётные и нормативные правила

По отдельному разрешению пользователя 15.10.2026 исправлена L08: рабочий
legacy не подставляет NPSHa=8 м ни при пустом поле, ни при явном нуле.
Неизвестный запас - незавершённая проверка; неверное значение очищает старый
результат. Архив неизменён. Отдельный баланс `pump_suction.py` и HTML-блок
используют методику CNP CDM/CDMF, с. 18, с явными давлением/его видом,
отметками, потерями при максимальном рабочем режиме и Hv по температуре.
Hгар, отметка ввода, прежние потери и Qрасч не подменяют эти данные.
Результат не переносится автоматически в подбор/проект. Минимум Hs=0,5 м
виден; полный баланс сравнивается без округления. Проверка одного режима
не разрешает пуск. Область и тесты: `docs/pump_suction_2026-10-15.md`.

Компоновка вводного учёта (согласовано 14.10.2026): в новых проектах Studio
по умолчанию один общий ВУ; галочка «Отдельный ВУ на каждом вводе» включает
прежний вариант. Число вводов и число одинаковых ВУ - разные величины.
Старые YAML и сохранённые черновики сохраняют прежнюю топологию, пока
пользователь её не изменит; подписанный пример Самары не переписывается.
Расход/потери счётчика не делятся на число вводов. Исключение п. 12.12 СП30
для двух отдельных счётчиков нельзя переносить на один общий: в общем
варианте принята сервисная обводная, её DN/изделие без данных не назначаются.
Ответвления В2 до учёта сохраняются на отдельных вводах; общий ВУ не
превращает их в одну пожарную подводку. Граф границ `metering_supply.py`
используется вместе с `MeteringChain` в обслуживании, схеме и спецификации.
Границы учёта/переключения требуют соответствия ТУ; это не универсальное
утверждение о пригодности одной схемы для всех объектов.

Проверка обслуживания ВУ (согласовано 14.10.2026): используем связность
`MeteringChain` и `app/pz/maintenance_engine.py`, не координаты рисунка.

обводную/подпор здания; обратный клапан не считается ремонтной отсечкой,
снимаемая арматура не изолирует сама себя. Сброс давления, слив и впуск
воздуха проверяются независимо. Контрольный кран не считается нижним сливом
по одному факту наличия. Неизвестный профиль/карманы не дают успешной проверки.
Диагностика не разрешает физическую разборку, не заменяет расчёты и не добавляет
неподобранные изделия в спецификацию. Границы: `docs/metering_maintenance_2026-10-14.md`.

связь вводов до счётчика не считается доказанным перетоком или его отсутствием:
нужны давления наружной сети/ТУ. Неизвестное положение не подтверждает подачу,
но учитывается при поиске возможных опасных путей. Границы сети не являются

Без привязки расчётных участков к новой обвязке её потери не считаются нулевыми
или уже включёнными в старую сумму. Комплектные элементы подтверждённой PBS
учитываются в одной строке НУ, без повторных отдельных закупок.

готовой программой ПЛК; неизвестные сигналы не разрешают пуск. В2 и другие
неподдержанные топологии не наследуют этот алгоритм.
